# Chapter 10: Audio

Scope: every sound asset the game can play (24 cooked assets under `/Game/Ironwake/Audio`), the source WAV each came from, how the procedural ones were generated (`build/audio/gen.py` parameters), loop lengths and loop flags, what triggers each sound, the volume/pitch rules against speed, sea state, wind, rain and weather, the music rules, attenuation settings, and the spectrum (hum) checks that exist. Since P18 (10.12) there are eight Sound Classes with a slider per class in the AUDIO settings tab; before P18 there was no volume UI and levels were set per sound in code (those per-component levels are still the base the class volumes multiply). Numbers come from the files cited; durations/sample rates come from `docs/spec/audio_probe.txt` (an `ffprobe` dump of `Audio/*.wav`, one line per file: `name sample_rate,channels,duration_s`, produced by this chapter's author). Citation: `value` [src path:line].

## 10.3 Generator: `build/audio/gen.py`

Writes mono 16-bit WAVs into `Audio/<name>.wav` (relative to the project root; run from there). Method: white Gaussian noise in the FFT domain shaped by a smooth band-pass gain, then a slow periodic amplitude modulation (low-passed noise, exactly periodic so the loop is seamless), then peak-normalised. No tonal content by construction.

| Parameter | Value | Source |
|---|---|---|
| Sample rate | `SR=48000` [src build/audio/gen.py:4] | build/audio/gen.py |
| Length | `N = SR*20` = 20 s [src build/audio/gen.py:4] | |
| RNG seed | `default_rng(11)` [src build/audio/gen.py:17] (one generator shared in order bow, wake, hiss) | |
| Default AM depth / rate | `am=0.25`, `amhz=0.7` | `am=0.25, amhz=0.7` [src build/audio/gen.py:5] |
| AM filter | low-pass band `f < 2*amhz` with Gaussian roll-off `exp(-(f/amhz)^2)`, normalised to peak 1 | `amhz*2` [src build/audio/gen.py:10] |
| Band gain `bump(f, lo, hi, slope)` | `1/sqrt(1+(lo/f)^(2 slope)) / sqrt(1+(f/hi)^(2 slope))` | `def bump` [src build/audio/gen.py:14] |
| `bow_wash_loop` | `bump(f, 250, 3000, 1.0) * (f/1000)^-0.2`, `am=0.3` (default `amhz`) | `bump(f,250,3000,1.0)` [src build/audio/gen.py:19] |
| `hull_wake_loop` | `bump(f, 70, 2200, 0.7) * (f/300)^-0.15`, `am=0.35`, `amhz=0.5` | `bump(f,70,2200,0.7)` [src build/audio/gen.py:20] |
| `hull_hiss_proc` | `bump(f, 900, 6000, 1.0)`, `am=0.2`, `amhz=1.0` | `bump(f,900,6000,1.0)` [src build/audio/gen.py:21] |
| Output level | peak scaled to `0.5` (-6 dBFS), "in-game volume handles level" | `*0.5` [src build/audio/gen.py:24] |

Not generated by this script (generator not in the repo, so the exact parameters are unknown): `bow_rush_proc`, `harbour_lap_proc`, `wind_sea_proc`, `gale_proc`, `rain_proc`, `surf_proc` (CREDITS.md says filtered noise via ffmpeg for the last four named there [src [REDACTED]/Projects/game-concepts/ironwake/audio/sfx_cc0/CREDITS.md:14]), and `thunder_near`/`thunder_far`. The thunder recipe proposed in USE.md is "brown noise burst, lowpass 300 Hz, 3-6 s exponential decay" [src [REDACTED]/Projects/game-concepts/ironwake/audio/sfx_cc0/USE.md:13] and W2 notes "synthesised thunder_near/far.wav" [src build/logs/W2.md:19]; which exact script produced the shipped files is unknown (recover by spectrogram, or search the W2 session log).

**CONFLICT (P11 card vs gen.py):** the P11 card asked for bow wash band `300-3000 Hz`, wake `80-800 Hz`, hiss `1-6 kHz` [src build/cards2/P11_world_audio_help.md:13]; `gen.py` as shipped uses band corners `250/3000`, `70/2200`, `900/6000` as tabulated above. The script is what produced the files in `Audio/`, so the script wins.

## 10.4 Player/NPC water loops (`TickWaterAudio`)

Called every tick for each non-sinking ship [src Source/IronwakeTest/IronwakeShipPawn.cpp:767]. Five looping `UAudioComponent`s are created once per ship, attached to `HullBody`, started at a random offset `FRand()*4` s with volume multiplier `0.001`:

| Component | Asset | Attach point | Source |
|---|---|---|---|
| `SndBow` | `bow_wash_loop` | bow, `X1*100` | `bow_wash_loop` [src Source/IronwakeTest/IronwakeShipHydro.cpp:280] |
| `SndWake` | `hull_wake_loop` | stern, `X0*100` | `hull_wake_loop` [src Source/IronwakeTest/IronwakeShipHydro.cpp:281] |
| `SndLap` | `slow_lap_loop` | origin | `slow_lap_loop` [src Source/IronwakeTest/IronwakeShipHydro.cpp:282] |
| `SndRush` | `bow_rush_proc` | bow | `bow_rush_proc` [src Source/IronwakeTest/IronwakeShipHydro.cpp:284] |
| `SndHiss` | `hull_hiss_proc` | origin | `hull_hiss_proc` [src Source/IronwakeTest/IronwakeShipHydro.cpp:285] |

Attenuation (per ship): spatialised, inner shape extent `40000` cm (400 m) for the player, `4000` cm (40 m) for NPCs; falloff distance `120000` cm player, `60000` cm NPC [src Source/IronwakeTest/IronwakeShipHydro.cpp:261-262].

Gain curves (`Kn` = speed in knots clamped >= 0; `Frac = clamp(Kn/13, 0, 1.2)`, 13 kn = FULL AHEAD; `Own` = `1` player, `0.45f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:291] NPC):

| Layer | Volume multiplier | Pitch multiplier | Source |
|---|---|---|---|
| Slow lap | `clamp(1 - Kn/4, 0.15, 1) * 0.7 * Own` (never fully silent; `0.105` floor) | none | `Kn / 4.f, 0.15f, 1.f) * 0.7f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:292] |
| Bow wash | `(SmoothStep(0.05, 0.9, Frac)*0.95 + clamp(BowSubmergeM+1, 0, 2)*0.15*Frac) * Own` | `0.95 + 0.1*clamp(Frac,0,1)` (+/-5 %) | `SmoothStep(0.05f, 0.9f, Frac) * 0.95f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:293], `0.95f + 0.1f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:295] |
| Wake | `SmoothStep(0.1, 1, Frac) * 0.8 * Own` | `0.95 + 0.1*clamp(Frac,0,1)` | `SmoothStep(0.1f, 1.f, Frac) * 0.8f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:294] |
| Bow rush | `clamp(Kn/10,0,1) * 0.9 * Own * Dr1` (0 at rest, full at 10 kn) | `0.9 + 0.2*clamp(Kn/12,0,1)` | `Kn / 10.f, 0.f, 1.f) * 0.9f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:301] |
| Hull hiss | `clamp(Kn/8,0,1) * 0.7 * Own * Dr2` (full at 8 kn) | none | `Kn / 8.f, 0.f, 1.f) * 0.7f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:302] |

Random drift so loops do not repeat audibly: `Dr1 = 0.88 + 0.12*sin(t*0.23+1.3)*sin(t*0.071)`, `Dr2` the same form with `0.17f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:300] and `0.053f` [src Source/IronwakeTest/IronwakeShipHydro.cpp:300]. All volume values are floored at `0.001` (never exactly zero, so the loops keep playing).

There is **no** dependency on sea state, weather or rain in these five layers except `BowSubmergeM` in the bow wash term. Sea state affects audio only through the storm layers (10.5).

## 10.5 Wind / rain / storm layers (`AIronwakeStorm::TickAudio`)

Five looping, **non-spatialised** (`bAllowSpatialization = false`) components attached to the storm actor, started at random offset `FRand()*5` s [src Source/IronwakeTest/IronwakeStorm.cpp:58-66]. Order and assets: `wind_sea_proc`, `gale_proc`, `storm_howling_wind`, `rain_proc`, `creak_storm_strain`. `Wind` = `IronwakeFleet::WindKn(World)`; `Local` = local sea state (0 CALM .. 4 STORM).

| Layer | Volume rule | Source |
|---|---|---|
| 0 `wind_sea_proc` | `clamp(Wind/20, 0.15, 1) * 0.55 * (1 - 0.5*SmoothStep(30, 45, Wind))` | `Wind / 20.f, 0.15f, 1.f) * 0.55f` [src Source/IronwakeTest/IronwakeStorm.cpp:268] |
| 1 `gale_proc` | `SmoothStep(24, 36, Wind) * 0.9` | `SmoothStep(24.f, 36.f, Wind) * 0.9f` [src Source/IronwakeTest/IronwakeStorm.cpp:269] |
| 2 `storm_howling_wind` | `SmoothStep(38, 48, Wind) * 0.8` | `SmoothStep(38.f, 48.f, Wind) * 0.8f` [src Source/IronwakeTest/IronwakeStorm.cpp:270] |
| 3 `rain_proc` | only while the rain Niagara is active: `Lerp(0.25, 0.9, max(RainAmount, Storminess))`, else `0` | `Lerp(0.25f, 0.9f, FMath::Max(RainAmount` [src Source/IronwakeTest/IronwakeStorm.cpp:271] |
| 4 `creak_storm_strain` | only on a sailing ship and `Local >= 2.8`: `SmoothStep(2.8, 4, Local) * 0.75`, else `0` | `SmoothStep(2.8f, 4.f, Local) * 0.75f` [src Source/IronwakeTest/IronwakeStorm.cpp:272] |

Pitch is not modulated on any storm layer. Wind speed per weather/sea state is chapter 3/8.

**Random hull creaks** (sailing ships only): every `FRandRange(6, 20)` s, scaled faster by roll (`CreakIn -= Dt * (1 + |Roll|/6)`), plays `creak_wooden_hull` 2D at volume `clamp(0.35 + Wind/60, 0.3, 1.1)`, pitch `FRandRange(0.85f, 1.1f)` [src Source/IronwakeTest/IronwakeStorm.cpp:282].

**Thunder** (storm director; needs `Storminess() >= 0.6`, else the next strike is pushed `6` s): next strike every `FRandRange(7, 18) / max(St, 0.6)` s; strike distance `FRandRange(900, 7000)` m; the sound arrives `DistM / 343` s later; `thunder_near` if distance `< 2800` m else `thunder_far`; volume `Lerp(1.6, 0.6, DistM/7000)`; pitch `FRandRange(0.85, 1.05)`; played 2D [src Source/IronwakeTest/IronwakeStorm.cpp:232-246]. The flash is visual (chapter 8/3).

## 10.10 Spectrum checks and results

## 10.12 P18 sound classes, mix and AUDIO tab (2026-11-11)

**Assets.** `/Game/Ironwake/Audio/Classes/SC_Master` (root) with seven children `SC_Music`, `SC_Sea`, `SC_Wind`, `SC_Ship`, `SC_Guns`, `SC_Voices`, `SC_UI` (`SC_UI` has `bIsUISound` so menu sounds play while paused). Every one of the 25 cooked sounds has `SoundClassObject` set by `Content/Python/iw_p18_audio.py`; `[/Script/Engine.AudioSettings] DefaultSoundClassName` is `SC_Master`, so a sound with no class plays under MASTER only and `IronwakeAudio::Init` logs `IWAUDIO unclassed <name>` at game start. New sound `ui_click` (generated 90 ms band-passed noise tick, `Audio/ui_click.wav`) is the menu click and the UI test sound.

| Class | Sounds |
|---|---|
| MASTER (default 80) | root of all; also the only class of an unclassed sound |
| MUSIC (default 0 = off) | main_theme, battle_night_storm |
| SEA & WATER (100) | bow_wash_loop, hull_wake_loop, hull_hiss_proc, slow_lap_loop, bow_rush_proc, harbour_lap_proc, surf_proc |
| WIND & WEATHER (100) | wind_sea_proc, gale_proc, storm_howling_wind, rain_proc, thunder_near, thunder_far |

| VOICES (100) | captain_contact, captain_load, officer_correct, officer_damage, officer_splash |

Engines and sails have no sound in the project, so SHIP & HULL holds the creaks, impacts and groundings only (the card's "engine/steam, sails" classes will take sounds added later).

**Runtime** [src Source/IronwakeTest/IronwakeAudio.cpp]. A transient `USoundMix` is pushed once per world; `SetSoundMixClassOverride(mix, class, volume, 1, 0.05 s fade, bApplyToChildren = (class == Master))` is set for all eight classes on every change, so the engine multiplies `component volume x class override x parent (MASTER) override` for every playing sound, including loops already running. This multiplies the existing speed/wind-driven component volumes in 10.4-10.7; no component code changed. Values live in `[Ironwake] Vol_Master|Music|Sea|Wind|Ship|Guns|Voices|UI` (percent) in GameUserSettings, are applied in `BeginPlay` (`IronwakeAudio::Init`) and live while the slider moves (the menu tick snaps to 5 % steps and applies). `-iwvol=<Class>:<0-100>` (repeatable) overrides for one run without saving. Console: `IWVol <Class> <pct>`, `IWAudioTest`.

**Music rule.** `IronwakeSettings::GetMusic()` is `MUSIC > 0`; moving the slider across 0 calls `ApplyMusicToShips()` (stops or fades in the calm track). Music is therefore off by default and plays only above 0; its loudness is `0.55 x MUSIC x MASTER`.

**TEST button.** Plays a 3 s sample at the slider level only when pressed (Enter / A on a focused slider does the same): MASTER foghorn_sfx (class override = MASTER only), MUSIC main_theme, SEA slow_lap_loop, WIND wind_sea_proc, SHIP creak_wooden_hull, GUNS broadside_sfx, VOICES officer_splash, UI ui_click. RESET AUDIO restores 80 / 0 / 100 x 6.

**Proof (no sound played, `-nosound`):** `-iwaudiotest` writes `build/logs/P18_audio_routes.txt`: class tree (all seven children report parent `SC_Master`), then for each of the 25 sounds its class and the effective multiplier (class chain x master x the component's peak volume) with all sliders at 0 / 50 / 100 %, with only its own class slider at 0 / 50 / 100 %, and master 0 (largest effective multiplier over all sounds = 0.000). Result: 25 sounds, 0 unclassed, 0 tree problems. The report is computed from the cooked assets; with `-nosound` there is no audio device to query a live mix, and no listening test was done (Chuck is not asked to listen during runs).
